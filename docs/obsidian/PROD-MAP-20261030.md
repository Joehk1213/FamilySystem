## Environment-file separation (host app vs Docker Compose)

The repository does not contain files literally named `.env.host` or `.env.docker.host` (nor do those names exist in `D:\backup\`). Current production setup separates responsibilities as follows:

- **Host Node/PM2 process environment:** `DOTENV_CONFIG_PATH` points to the protected production env file under `D:\backup\`; this config supplies the Node app settings. PM2 process-list save succeeded. Never print or copy its values into this map.
- **Docker Compose interpolation:** run Compose with `--env-file .env.docker`; this supplies stack variables such as the D: bind-mount root. The Compose environment is not a substitute for the PM2 app's `DOTENV_CONFIG_PATH`.

Treat -host env- and -Compose env- as distinct roles, not as claims that the absent alias filenames are present. Keep both files and all key values out of Git and logs.

## Real BGE and encryption

- RAG uses the local BGE-small-zh model, real 512-dimensional vectors, and local-only model loading. It must not download weights or send inference to an external AI service. The legacy placeholder is 384D and uses a separate database column; do not mix dimensions.
- PostgreSQL has `pgcrypto` and `public.records.encrypted_content BYTEA`. v1.0 encrypts private record body content via the pgcrypto application/RPC path and decrypts only for authenticated callers permitted by RLS. The encryption key is supplied through the protected runtime environment; no key is recorded here.
- This encryption scope does not encrypt titles/all metadata or family-memory/RAG content; it is not end-to-end encryption and there is no key rotation. Preserve a controlled key recovery/backup process.
