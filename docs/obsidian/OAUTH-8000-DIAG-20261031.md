# OAuth port 8000 diagnosis — JOE-SERVER

Checked: 2026-10-31 15:21:43 +08:00
Scope: read-only diagnostics. No firewall, Docker, OAuth, or environment configuration was changed. No credential values are included.

## Port binding and Docker
- `netstat -ano` shows `127.0.0.1:8000` LISTENING (PID 13360, `com.docker.backend`); there is no `0.0.0.0:8000` listener.
- `docker-compose.prod.yml` publishes gateway as `127.0.0.1:8000:80`, so it is reachable on SERVER loopback only, not the LAN/Tailscale interfaces.
- Docker Compose reports db, auth, storage, rest, and gateway running; db/auth/storage/gateway report healthy. The deployment has no public host binding for gateway port 8000.

## Windows Firewall
- Rule `FamilySystem 8000 Tailscale+LAN`: Enabled, inbound TCP, local port 8000, Action Allow, Domain/Private/Public profiles, RemoteIP Any.
- The rule is permissive across all remote IPs; it was not changed. `Get-NetFirewallPortFilter` was denied by local permissions, but `netsh advfirewall firewall show rule` successfully returned the rule details.
- An allow rule does not override the Docker loopback-only port publish; the observed connection failure is consistent with the bind.

## Auth health reachability
- SERVER `http://127.0.0.1:8000/auth/v1/health`: HTTP 200; GoTrue health response.
- SERVER `http://joe-server:8000/auth/v1/health`: connection failed (curl exit 7; HTTP 000).
- SERVER LAN interface `192.168.1.136:8000`: connection failed (curl exit 7; HTTP 000).
- `joe-server` resolves to the SERVER LAN address plus other interface addresses. This session runs on SERVER; an independent Desktop-origin test could not be executed here. The hostname/LAN probe from SERVER also fails.

## OAuth/Auth configuration (effective Auth container values)
- `GOTRUE_EXTERNAL_GOOGLE_ENABLED`: true.
- Google Client ID: configured (presence only); Google secret: NOT configured. Secret values were not read or printed.
- `GOTRUE_SITE_URL`: `https://family.example.invalid` (placeholder; does not match `http://joe-server:3002`, `http://joe-server:8000`, or a Tailscale address).
- `API_EXTERNAL_URL`: `https://family.example.invalid/auth/v1` (placeholder).
- `GOTRUE_URI_ALLOW_LIST`: `http://localhost:3002`, `https://family.example.invalid`; it does not include `http://joe-server:3002/*` or Tailscale redirect URLs.
- `.env.docker` has matching `SITE_URL`, `API_EXTERNAL_URL`, and `ADDITIONAL_REDIRECT_URLS` values; Google Client ID is present and Google secret is unset. `supabase/config.toml` has no matching Google/Auth URL overrides.

## Diagnosis
Two independent blockers are confirmed: (1) Docker gateway port 8000 is published only on 127.0.0.1, causing `joe-server:8000` timeouts from non-loopback clients; (2) OAuth configuration still uses the `.invalid` placeholder and localhost-only redirect allow-list, with Google secret absent. The firewall already allows TCP/8000, but that cannot compensate for the loopback-only Docker bind. This report does not apply fixes.
